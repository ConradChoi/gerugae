# 거르개 — 설계 문서

- **작성일**: 2026-09-17
- **서비스명**: 거르개
- **한 줄 정의**: 프리랜서가 함께 일하는 원천사/에이전시를 리뷰하고, 관련 정보를 공유하는 가입제(회원제) 웹 서비스

## 1. 배경 및 목적

프리랜서는 웹에이전시, 인력회사 등 원천사를 거쳐 일하는 경우가 많은데, 이 과정에서 만나는 업체 중 좋지 않은 곳들이 많다. 프리랜서들이 이런 기업에 대한 리뷰와 정보를 공유해 더 나은 계약 환경을 만드는 것을 목표로 한다.

- **주 사용자**: 프리랜서
- **공개 범위**: 가입/초대제 — 회원가입(로그인) 후에만 열람 가능, 검색엔진 노출 여부는 별도 제한하지 않음

## 2. MVP 스코프

| 포함 | 제외(향후) |
|---|---|
| 기업(원천사/에이전시) 등록 | 기업 인증/공식 대응 계정 |
| 기업 리뷰(별점+태그+텍스트) | 리뷰/글에 대한 댓글 |
| 정보공유 글(팁/Q&A) | 신고/제재 자동화, 관리자 콘솔 |
| 마이페이지(닉네임 수정, 내 글/리뷰) | 모바일 네이티브 앱 |
| 이메일/비밀번호 가입 | 실명/사업자 인증, 소셜 로그인 |

## 3. 전체 아키텍처

- **프론트엔드**: Next.js (App Router), 반응형 웹
- **백엔드**: Supabase (Auth + Postgres). 별도 API 서버 없이 Supabase 클라이언트에서 직접 CRUD, Row Level Security(RLS)로 접근 제어를 수행
- **인증**: Supabase Auth 이메일/비밀번호 로그인. 스팸 계정 방지를 위해 이메일 컨펌 활성화
- **접근 제어**: 비로그인 사용자는 목록/상세를 열람할 수 없다. 비로그인 방문자에게는 서비스 소개 및 가입 유도 랜딩만 노출한다 (RLS + 라우트 가드 이중 적용)
- **향후 이전 대비**: Supabase 전용 기능(Realtime, Storage 등)은 초기에 최소한으로 사용하고, 스키마는 표준 Postgres로 설계하여 향후 자체 DB/서버로 이전 시 마이그레이션 부담을 최소화한다

**작성자 노출**: 모든 게시물은 닉네임으로만 노출되며, 이메일 등 개인정보는 어디에도 공개되지 않는다.

## 5. 접근 제어 (RLS 정책)

- `companies`, `reviews`, `community_posts`
  - SELECT: 로그인 사용자(`auth.uid() IS NOT NULL`)만 허용
  - INSERT: 본인 명의로만 (`author_id = auth.uid()` 또는 `created_by = auth.uid()`)
  - UPDATE/DELETE: 작성자 본인 소유 row만 (`author_id = auth.uid()`). companies는 등록자 외 수정 불가(향후 신고 기능으로 오정보 처리)
- `profiles`
  - UPDATE: 본인 row만 (닉네임 수정)
  - SELECT: 로그인 사용자 전체에게 닉네임 조회 허용(작성자 표시용)

## 6. 주요 화면/플로우

1. **랜딩(비로그인)**: 서비스 소개, 면책 문구("게시물은 작성자 개인 의견이며, 본 서비스는 게시물 내용에 대해 법적 책임을 지지 않습니다" 등), 가입/로그인 유도
2. **가입/로그인**: 이메일/비밀번호 + 닉네임(가입 시 1회 입력)
3. **기업 검색/목록**: 이름 검색, 결과 없을 시 "새 기업 등록" 유도
4. **기업 상세**
   - 리뷰 탭: 평균 별점, 태그별 필터, 리뷰 목록
   - 정보공유 탭: 팁/Q&A 목록
5. **리뷰 작성**: 별점 + 태그(다중 선택) + 자유텍스트. 기업당 1회, 이후 수정만 가능
6. **정보글 작성**: 제목 + 내용
7. **마이페이지**: 닉네임 수정, 내가 쓴 리뷰/글 목록

## 7. 법적 고지 관련 참고사항

가입 시 작성된 게시물이 개인 의견이며 서비스가 법적 책임을 지지 않는다는 면책 문구를 노출하기로 했다. 다만 국내법(정보통신망법 등)상 면책 문구만으로 플랫폼의 책임이 전부 면제되지는 않으므로, 다음 항목은 이후 단계에서 별도로 검토가 필요하다 (본 스펙의 구현 범위에는 포함하지 않음):

- 명예훼손/허위사실 신고 접수 및 임시조치(블라인드) 절차
- 이용약관·개인정보처리방침 문서화

## 8. 테스트 계획

- Supabase RLS 정책 단위 테스트: 비로그인 차단, 본인 소유 row만 수정/삭제 가능, 타인 리뷰 수정 시도 차단
- 핵심 플로우 E2E: 가입 → 기업 등록 → 리뷰 작성 → 목록/상세 조회
- 유니크 제약(기업당 리뷰 1회) 위반 시 에러 처리 확인
- 닉네임 수정 반영 확인(마이페이지)

## 9. 향후 고려사항 (스코프 외)

- 리뷰/정보글 댓글 기능
- 신고/블라인드 처리, 관리자 콘솔
- 기업 중복 등록 병합 로직
- 자체 DB/서버로의 마이그레이션
- 모바일 네이티브 앱
